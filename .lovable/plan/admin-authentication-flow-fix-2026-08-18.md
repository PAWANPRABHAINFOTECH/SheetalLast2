# Admin Authentication Flow Fix

The user is being redirected to a Lovable internal page when clicking "Verify Email" or "Reset Password" links because the Supabase `Site URL` or `Redirect URLs` in the backend configuration likely point to the Lovable management internal origin (`lovable.dev` or the internal editor frame) instead of the actual public website URL.

## Changes

1. **Verify Backend Configuration**: I will check the Supabase Site URL and Redirect URLs. Since I don't have a direct tool to read these config values, I will attempt to set them explicitly using `supabase--configure_auth` (if it supported these, but it doesn't). Instead, I will use `supabase--configure_oauth_server` if needed, but the primary fix for email links is ensuring the `redirectTo` in our code is correct AND the backend allows it.
2. **Explicit Redirect URLs**: I will use a migration to ensure the `auth.has_role` and other security functions are correct, and I will ensure that the `redirectTo` parameter in our `resetPasswordForEmail` call uses the strictly correct origin.
3. **Auth Callback Route**: I will enhance the `/auth/callback` route to handle the transition from the verification link to the password setup page more robustly, ensuring it reads tokens from the URL correctly even if the initial page load has a complex hash.
4. **Site Settings Update**: I will verify the `site_settings` table to ensure the site's own URL is correctly stored if it's used for any internal link generation.

## Technical details

- **Problem**: Supabase's default "Site URL" for Lovable projects often defaults to the internal management frame (`*.lovableproject.com`), which users cannot access directly. When an auth email is sent, if the `redirectTo` isn't strictly matched or if the "Site URL" is wrong, the link generated by Supabase may default to that internal URL.
- **Fix**: 
  - Update `src/routes/admin.login.tsx` to use the most reliable origin detection.
  - Enhance `src/routes/auth.callback.tsx` to handle the `recovery` type and session injection.
  - Set the Supabase Redirect URLs to include the public dev and production URLs.

```text
Email Link -> Supabase Auth -> Redirect to /auth/callback -> Redirect to /admin/reset-password
```
